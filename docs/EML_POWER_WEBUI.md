# EML power, link feedback, cooling and WebUI (P8)

This document separates firmware-visible configuration from measurements that
still require the ES900 hardware bench. A power enum or DAC code is never treated
as proof of conducted RF output.

## Power paths

### ES900TX external PA

The embedded `HappyModel ES900` TX layout exposes the complete nominal sequence
`10/25/50/100/250/500/1000 mW` (`power_min=0`, `power_max=6`). GPIO25 drives the
external PA APC DAC with layout codes `41, 60, 73, 90, 110, 132, 190`; GPIO12 is
TX_ENABLE and GPIO13 is RX_ENABLE. These seven numbers are board-specific DAC
control codes, not dBm values. The same layout is embedded byte-for-byte in
`HappyModel_ES900TX_Bridge` and `HappyModel_ES900TX_as_RX_Bridge`, so the FEM is
switched by the existing `RFAMP.TXenable/RXenable` path in either protocol role.

The correspondence between those codes and conducted power at every EML band is
pending the P8.1/P8.6 hardware sweep. Until then the WebUI calls the levels
*nominal* and caps selection to the layout's maximum.

### ES900RX PA_BOOST

The RX layout table covers 10/25/50 mW. Bridge builds add a bounded 100 mW level
using the SX1276 documented +20 dBm sequence:

| Register | 100 mW setting | Normal setting |
| --- | ---: | ---: |
| `RegPaConfig` (`0x09`) | `0x8F` (`PA_BOOST`, `OutputPower=15`) | layout value |
| `RegOcp` (`0x0B`) | `0x32` (OCP on, 150 mA) | `0x32` |
| `RegPaDac` (`0x4D`) | `0x87` | `0x84` |

The register update is deferred until Standby exactly like existing SX127x power
changes. RF TX/RX selection remains in `TXnb`/`RXnb` through `RFAMP`, so changing
the logical Bridge role cannot leave the PA enabled in receive mode. The
register policy and limit are native-tested; actual 20 dBm output and current are
pending P8.2/P8.6 bench measurements.

## EML link feedback and Dynamic Power

Each direction sends a session-bound control record in its reserved anchor once
per 64 slots. It carries PHY, LQ, PER, averaged RSSI and, only for LoRa, averaged
SNR plus an explicit `snr_valid` bit. FSK never invents or consumes LoRa SNR.
These records use fixed SYNC/control frames and never enter the UART byte queues.

Dynamic Power consumes the peer's report, because it describes reception of this
node's transmitter. Its policy is:

- clamp every change to the board minimum and the WebUI-selected maximum;
- raise one level on LQ below the configured degradation threshold, excessive
  PER, or RSSI below -105 dBm, with a 250 ms rate limit;
- lower one level only after five continuous seconds at LQ >=95%, PER <=5%,
  RSSI >=-75 dBm and, when LoRa SNR exists, SNR >=5 dB;
- after reports have begun, two seconds without feedback selects the configured
  maximum and clears the down-ramp hold;
- when Dynamic Power is disabled, the selected power remains fixed.

Metrics consume two full slots per 64-slot schedule (one per endpoint). Frame
size, radio bitrate, time-on-air and slot interval are unchanged from P7; the
capacity cost is 3.125% of aggregate slots and therefore requires no new ToA
budget. Negotiated band/TDD control has priority while an exchange is active.

## Cooling

The ES900TX layout maps the enable-only fan to GPIO17. In every ESP32 Bridge role
the fan uses the WebUI threshold (250 mW by default), waits four one-second
cycles before starting, and remains on for `fan-runtime` seconds after power
drops below the threshold. The same logic therefore applies to both modules of a
2x ES900TX pair. The layout declares no LM75A, PWM, or tachometer, so firmware
does not claim a temperature measurement or closed-loop thermal regulation.
GPIO behavior, fan start-up and safe temperature at 250/500/1000 mW remain
hardware acceptance items P8.5/P8.6.

## Minimal Bridge WebUI

`src/html/eml-bridge.html` is standalone vanilla HTML/CSS/JS. Its deterministic
gzip asset is generated by `src/python/generate_eml_web.py` and selected only for
`EML_BRIDGE` builds. After the P9 role and traffic-mode controls the current
payload is 2630 bytes (2588 before the Auto role option), below the 5 KiB limit.
It provides:

- `/update` `.bin` upload with progress, `/reboot`, and board/firmware data from
  `/bridge-info.json`;
- settings persisted through `/options.json`: default band, adaptive band
  fallback, LQ threshold, PHY, 57600/115200/230400/420000/460800 baud, UART
  inversion, symmetric/adaptive TDD, fixed/maximum power, Dynamic Power, fan
  threshold and minimum fan runtime;
- a visible but disabled GFSK 500k choice. The API also rejects it with HTTP 422:
  SX1276 is specified to 300 kbit/s and P5.7 hardware qualification is pending.

Radio-policy settings are included in the EML configuration ID where needed, so
mismatched peers do not silently open an incompatible session. A reboot applies
saved UART/radio settings. Wi-Fi recovery and UART bootloader entry remain intact.

## Alternative roles and static verification

| Environment | MCU / hardware layout | Protocol role | RAM | Flash | IRAM used / free |
| --- | --- | --- | ---: | ---: | ---: |
| `HappyModel_ES900TX_Bridge` | ESP32 / ES900TX | coordinator | 61,376 | 1,061,813 | 85,560 / 45,512 |
| `HappyModel_ES900RX_Bridge` | ESP8285 / ES900RX | responder | 44,128 | 466,304 | 33,761 / 15,391 |
| `HappyModel_ES900RX_as_TX_Bridge` | ESP8285 / ES900RX | coordinator | 42,168 | 465,996 | 33,149 / 16,003 |
| `HappyModel_ES900TX_as_RX_Bridge` | ESP32 / ES900TX | responder | 54,912 | 1,044,365 | 85,568 / 45,504 |

The alternative environments embed exactly the same hardware JSON as their
physical counterpart. All four images pass the build audit: Bridge entry point,
EML ISR presence/location, LittleFS/OTA/reboot recovery routes, removed RC stack,
and IRAM bounds. The ESP8285 coordinator has 16,003 bytes free IRAM, comfortably
above the required 5 KiB; the timer/DIO path is the same IRAM implementation used
by the responder, with role selected as a compile-time constant.

No radios were flashed during this implementation. Pair compatibility, actual
TDD waveform timing, RF output/current/temperature, fan electrical behavior and
WebUI/OTA operation on physical devices remain the explicit P8 hardware portion
deferred to stage 10.
